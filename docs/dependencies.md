# Внутренние и внешние зависимости

## 1. Внутренние зависимости

| Потребитель | Зависимость | Назначение |
|---|---|---|
| `ApiHost` | публичные сервисы модулей и `Contracts` | Прием HTTP-запросов и возврат DTO |
| `VehicleModule` | `CustomerModule` через публичный сервис/контракт | Проверка существования владельца |
| `ServiceOrderModule` | `CustomerModule`, `VehicleModule` | Проверка клиента и автомобиля перед созданием заказа |
| `ServiceOrderModule` | `WorkModule`, `PartsModule`, `PricingModule` | Получение состава заказа и расчета стоимости |
| `WorkModule` | `Contracts` | Обмен типами запросов и результатов |
| `PartsModule` | `Contracts` | Обмен типами запросов и результатов |
| `PricingModule` | контракты строк работ и запчастей | Расчет итоговой суммы |

Внутренние классы одного модуля не должны использоваться напрямую другим модулем. Для взаимодействия выбираются интерфейсы прикладных сервисов или публичные контракты.

## 2. Предполагаемые внешние зависимости

| Технология | Назначение | Статус |
|---|---|---|
| .NET 9 SDK | Сборка и выполнение приложения | Подтверждено заданием/выбрано |
| ASP.NET Core | HTTP API | Предлагается |
| Entity Framework Core | Доступ к данным | Предлагается |
| SQLite | Локальная база для учебной версии | Предлагается |
| xUnit | Модульные тесты | Предлагается |
| Microsoft.AspNetCore.Mvc.Testing | Интеграционные тесты API | Предлагается |
| Git / GitHub | Контроль версий и публикация этапов | Используется в рамках курсовой |

Пакеты и точные версии не зафиксированы до создания `.csproj`. Не следует считать перечисленные библиотеки уже установленными.

## 3. Правила добавления зависимостей

- Добавлять пакет только при наличии понятной потребности.
- Сохранять версию пакета в файле проекта.
- Не подключать пакет, если нужную задачу можно решить средствами платформы без существенного усложнения.
- Проверять совместимость с .NET 9.
- После изменения зависимостей выполнять `dotnet restore`, `dotnet build` и тесты.
